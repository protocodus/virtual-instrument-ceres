# Canonical DSP source

`Source/DSP/ceres.cpp` and `Source/DSP/ceres.hpp` are the only production DSP implementation. A host should pin this repository as a Git submodule and compile these files directly. Do not maintain a copied Rack-specific oscillator, filter or envelope implementation. The Rack project records the gitlink revision, embedded compile definition and compiled source inventory in its own release manifest.

The initial import is the tested canonical v0.10.0 model from `/tmp/ceres-cs50-1x8LGd`, recorded by original-file SHA256 in `EXPERIMENT_IMPORT.json`. The new product's version starts at 0.1.0. The experiment's isolated amplitude-bias, shared LP-bus and alternate decay candidates are deliberately absent. The temporary source is a provenance location, not a build dependency. Hardware recordings, downloaded schematics, fitting scripts and the large experiment archive were not imported.

## Embedded adaptation

`CERES_EMBEDDED_TARGET=1` removes `Patch::name`, native preset lookup and allocating measurement APIs. It adds no alternate sound model. The shared C-string and native string parameter setters accept the same numeric keys/ranges. The seven added panel controls extend the imported API; enum-like waveform/mode values clamp then round to the nearest declared integer. Invalid embedded construction rates fall back to 48 kHz; native construction retains its exception. Supported construction rates are finite 8000..384000 Hz. A host should validate its sample-rate property before construction.

The embedded library is compiled with `-fno-exceptions` in the native validation build. Its only owned heap allocation occurs during `Synth` construction; reset, panic, patch changes, configuration and processing reuse it. `Patch` is trivially copyable in this configuration. Native and embedded `Patch` layouts differ and must not be linked interchangeably. No filesystem, threading, SDK, plugin GUI, sample playback or host framework is used by the embedded translation unit. The current setter has 61 numeric keys, including four additions for sound-path control/output calibration, the optional expression-source selector, touch wah, the two glide controls and the expression pedal.

The allocation witness interposes `new`/`new[]` around 512 blocks of 64 samples with parameter/controller changes and lifecycle events, plus 64 blocks explicitly activating mixed-velocity expression and live source changes. It is a bounded witness, not exhaustive host testing or a blanket interception of every platform allocator. Source inspection finds no direct realtime `malloc`/allocation calls. The separate Rack wrapper must establish its own property/event and buffer contracts.

## Model and parameter boundaries

The default model has four free-running oscillator boards, finite oscillator reset, WSC waveform approximations, cascaded nonlinear two-integrator HP/LP filters, capacitor envelopes, per-voice/common output coupling, four-times oversampling and a 249-tap FIR decimator. Version 0.2.0 adds an explicit virtual 1–16 voice limit and 1×/2×/4× processing configuration; four voices at 4× retain the prior audio path. The additional qualities are a numerical/CPU tradeoff, not a source-circuit correction. Its normalized circuit voltages, nonlinear scales and several raw panel/preset-CV conversions remain provisional. Factory preset CVs pass the T71/T72 matrix diode (`Videal·(10−Vd)/10` at `I = Vpin/10k`, an estimated 1N4148-class curve for the unpublished 1S1555) before those conversions, so each pin lands 4.4–5.8 % below the guide's printed table. The full research archive contains public-recording diagnostics, but those did not establish exact hardware calibration, complete original MIDI/gates or a universal fit.

Filter frequency parameters specify the total small-signal integrator frequency at MIDI 60; a fixed 4.7-Mohm feed contribution remains while keyboard/envelope controls scale only variable conductance. Master `tune_cents` affects the oscillator and both filter keyboard paths; `octave` affects oscillator footage only. `key_track` is an engineering control, not proof of an alternative hardware law. Filter initial/peak levels and HP/LP envelope scales retain their explicit engineering units.

Engineering attack times mean initial-to-peak duration; decay/release mean T60 relative to the target. The native hardware table uses a separately documented, related-model five-RC conversion. `global_release` is an ideal shared minimum release-time override, distinct from MIDI damper gating and from the CS-50 SUSTAIN I/II keyboard-CV modes. Optional attack headroom/current-limit controls are research parameters, not identified chip controls. Once the clock runs, an idle filter envelope retains charge during IL edits and returns with its existing release coefficient; bookkeeping remains Idle. Pre-clock setup/reset may initialize the configured IL, and explicit panic retains its documented clear policy. Continuity is source-backed; the guide's ambiguous idle-gm wording prevents calling the chosen idle return rate a measured calibration.

Output coupling uses the documented topology with a low-input-impedance VCA limit, fully conducting expression element and unloaded HIGH output assumptions. The final stage is the PRA output preamp (SM2 printed p.22): linear `.18*volume` up to hard rails derived from the HA1452's 390/220 Ω supply droppers and the guide's 0 dBm HIGH-output reference (all volume controls full, four keys; printed pp.7 and 47), whose tone the shared-PRA CS-60 procedure gives as sine only (CS-60 service manual printed p.39), about 12 dB above that reference's peak, replacing the earlier uncalibrated `.9*tanh` rail; see [VCA and output research](research/vca-authenticity-2026-10-20.md). Downstream branch calibration and recording/interface loading remain uncertain. The direct sine bypass, absolute drive, Q/control calibration and oscillator reset duration must not be advertised as measured final values.

The model is deterministic within a given floating-point/compiler/math-library build. Cross-platform bit identity is not promised. No fast-math flag or silent oversampling reduction was introduced. Constructor-created FIR coefficients are built outside realtime processing. The bounded native tests do not establish a Reason target deadline: the four-voice nonlinear solver and decimator need separate 64-frame wrapper/SDK/host performance measurement.

## Added panel-control model

The ring/SUB-waveform/Sustain additions preserved the imported audio at ring mix 0, SUB sine and Sustain I in their historical regression. The later sound-path changes below intentionally correct nonzero SUB filter-depth settings and factory common-level placement. The ring bypass returns the previous bus value directly. New noise state consumes the existing shared white sample without another random draw, so oscillator initialization, noise and drift sequences remain unchanged. Native-only `voiceState()`, `modulationState()` and `soundPathState()` return read-only diagnostics; they are absent from the embedded ABI.

**Ring.** The Yamaha servicing guide and direct CS-50 PRA/Overall sheets put one ring processor after the voice sum, before expression/output. Its independent sine carrier traverses the documented four-100µF passive PRA network. The six resistor paths are 33kΩ pin7-to-ground, 100Ω pin7-to-pin8, 820Ω pin8-to-audio-bias, 1.2kΩ pin8-to-local-supply, 1kΩ audio-bias-to-ground and 390Ω local-supply-to-ground. The resulting differential voltage now drives the matched upper-pair steering law derived from the original Fairchild µA796 internal circuit: `tanh((DC + 1.5*passiveAC)/(2*VT))`. Yamaha's nominal source is3Vpp; the fixed25°C thermal voltage and unloaded external DC solution are explicit physical assumptions. No mean, peak or frequency-dependent gain normalization is applied. This adds source-grounded compression and even/odd carrier harmonics to the prior linear carrier product. The bus still enters a linear signal-port approximation, and the wet branch retains the direct-sheet10µF/10k output coupling (tau0.1s; the guide conflicts). The ideal carrier source, matched forward-active/infinite-beta upper transistors and zero IC DC/AC input loading do not identify the populated hardware operating point. Signal-port nonlinearity, loaded source amplitude, mismatch, wet gain trim and absolute hardware feedthrough remain uncalibrated; the model's nonzero DC feedthrough is not subtracted. See the historical [passive carrier checks](ring-carrier/README.md) and current [physical switching derivation and validation](ring-switching/README.md).

The carrier is free-running. An aggregate physical-key ledger, independent of board allocation and MIDI damper, triggers the frequency envelope only at all-keys-up → any-key-down, consistent with the owner's manual printed page 15. Additional key presses are legato. Final physical key-up interrupts the attack/decay and selects a fixed release. Direct CS-50 PRA (service2 PDF16/printed22) feeds RT through 6.8k from +15V and 3.3k to ground: the unloaded 4.9009901 V, interpreted through the existing provisional five-RC law, gives **0.46781044 s T60**. The ring's different external timing path prevents treating that inference as calibration. The envelope uses a 1% attack-target headroom, retains charge on retrigger/live edits and is independent of `global_release`. Attack is time to peak; decay is T60. Depth is a positive octave excursion, not recovered slider volts. The guide's approximate 0.2–220 Hz carrier range bounds the total frequency including the envelope; this is a bounded interpretation, not a measured analog clipping law.

**SUB.** Sine, down saw, up saw and square share the free-running SUB clock. Analytic BLEP corrections soften discontinuities; waveform phase/polarity alignment is an engineering convention. All existing SUB destinations, including pressure vibrato, use this selected source. The independent PWM sine clock is unchanged. Direct PN3 selects SUB-N; the guide printed page 32 shows a **22k/0.1µF low-pass**, distinct from audio NO level. Since 0.4.0 it is loaded by the SUI buffer's 100k to ground (service manual 2 p.8, PN3), giving an 88.26 Hz corner and a 100/122 divider. Although the guide calls this source pink noise and the owner's text calls it white noise, the implementation follows that one-pole circuit rather than an ideal 1/f generator. The shared limiter sample feeds the trapezoidal RC, scaled by the loaded ±15 V swing (±8.2 SUB units of 1.5 V). Its RMS is about 0.77 units at every rate (0.541 for an ideal sign without the pick-up coupling, both described under audio NO below). That level is an **estimate** through the limiter bandwidth and slew rate described there. Before 0.4.0 the level was an engineering 0.25 RMS with a tanh bound. There is no block normalization, gain follower, key sync or rate-dependent sample-and-hold.

**Sustain I/II.** The guide printed pages 25–26 describes held key voltages in I and open sample/hold gates in II. The model stores note ownership separately from sounding key voltage. In II, nonheld/nonpedal boards mirror `lastAssignedKey` on assignments, key release, pedal-up, all-notes-off and a live I→II switch. II→I captures the current key voltage. Both VCO and HP/LP keyboard paths use it, while oscillator phase, filter capacitors and amp/filter envelope state and gates remain unchanged. Allocation re-keys a released board holding the same key, then takes an idle board, the quietest released board, then the oldest damper-held board; a key pressed while every board is held is not stored, as the KAS timing chart shows (guide printed p.19). Exact Yamaha KAS scan timing is not emulated. Protecting MIDI-damper-held boards is an explicit modern adaptation because the original instrument's pedal path was expression. Ring's physical-key ledger ignores that damper protection. Panic clears voices and ring envelope/coupling while free oscillator phases continue; reset restores all seeded phases/controllers/states.

Validation covers independent RC attack/release equations, ring sidebands and dry/partial/wet signal connection, free-running carrier, more than four physically held keys, repeated presses, pedal rearm, sourced SUB-noise smoothing and route independence, and Sustain II's shared oscillator/filter pitch routing with continuous state. These are implementation checks, not hardware sound-match measurements.

## Shared cutoff/resonance controls and common VCA level

The primary components, page references, source hashes and an independent nodal calculation are in [the sound-path source audit](sound-path-gap-audit.md) and [its manifest](soundpath/source-manifest.json). This implementation uses an **anchored, stiff-source limit**: effective cutoff/resonance patch values remain the neutral reference. It does not reinterpret those existing values as raw preset voltages. Finite preset-bus impedances, passive pot taper/backfeed, chip control input current and individual calibration trims remain unidentified. These limits matter for absolute accuracy.

Factory presets are the exception for their own static filter values: their four filter columns are converted as the voltages the T-board rows actually hold. The board wiring lists (service manual 2 printed pp.11 and 15) run rows g and i straight to R7 FH/FL and rows h and j to QH/QL, with no buffer (the PRA followers serve only the PANEL cutoff levers). R7's four 39k branches into the M boards' pin-4 nodes load each cutoff row with about 10.3k beside its own 10k, and the four pin-7 networks load each Q row with 110k returning to RES, +10 V at the presets' RESONANCE MIN. Solving each row with its matrix diode puts factory cutoffs 0.5–1.6 octaves below the unloaded reading and lifts a zero Q column to 0.83 V (Q 1.58 → 1.44). Pin 4 is taken as a high-impedance input and the VR7/VR9 trims as centred, which bounds the cutoff buses to about ±0.06 V. The incremental controls keep the stiff-source limit: a board's EG or BR, by lifting its own pin-4 node, slightly unloads the shared bus (at most 0.1 octave with four full LP EGs), and away from MIN the RES lever drags a Q row with it (up to 13/24 instead of 1/2 of each volt at the pin); neither is modelled.

`hp_cutoff` and `lp_cutoff` stay total Hz at middle C. For front ends that show the PANEL HPF and LPF levers, `hpfLeverHz` and `lpfLeverHz` apply the hardware path: each B-10K lever spans 0–10 V (Servicing Guide printed p.35), a PRA follower (IC4, service manual 2 printed p.22) drives its T71 diode onto the same loaded FH/FL bus as the presets, and the printed law reads that bus. That gives 85 Hz at the bottom of the travel and about 42 kHz at the top, the diode taking 0.4–0.6 V over most of it. The LPF lever's top tenth lies above `lp_cutoff`'s 20 kHz ceiling, so on the lowest C a full LPF lever gives 10 kHz instead of the hardware's 21 kHz.

`brilliance` is a signed actual loaded BR-node voltage offset in volts, bounded −15..+15 with neutral 0. With preset/source nodes held stiff, the documented 39k manual path and BR paths 680k HP/220k LP give incremental octave gains `39/680` and `39/220` per volt: the FH/FL levers' 1 oct/V, which is Yamaha's printed IG00156 law `fc = 125·Kv·2^Vfc` (Servicing Guide printed p.34) with Vfc read at the 39k lever. That reading is the one inference, chosen by ear on 2026-10-20 (see [VCF research](research/vcf-authenticity-2026-10-20.md)). Brilliance adds to the variable-gm exponent alongside keyboard and EG control; it never scales the fixed 4.7 MΩ feed conductance. It is not a recovered panel slider position or an automatic recreation of the earlier loaded-bus diagnostic patches.

`resonance_offset` is a signed change of the actual RES bus around the effective Q calibration, bounded −10..+10 V, neutral 0. Positive electrical voltage reduces Q. The real wiper range is 0..10 V. Factory presets assume the RESONANCE lever at MIN (+10 V), so each pin 7 sits at the mean of its preset Q bus and 10 V, `r = (10 − P)/20`, and from them the lever reaches offsets 0 to −10 V; positive offsets have no lever position. The divider is printed; the MIN position was chosen by ear on 2026-10-20. Each of the eight pin-7 nodes has 220k to its preset source, 220k to the shared RES source and 10 µF to ground. With stiff sources, zero chip input current and equal initial incremental charge, those eight networks reduce exactly to one shared delta state:

`d(deltaVq)/dt = (resonance_offset/2 − deltaVq) / 1.1 seconds`.

The sample update is the exact constant-input RC solution at the internal rate. It is continuous through note allocation, patch changes and audio panic; returning the offset to zero retains the capacitor tail. Only `reset()` clears the incremental charge. The per-stage effective Q anchors now each follow the same1.1s pole through runtime edits, while the previous common-offset arithmetic is retained. These three computational coordinates decompose two physical stage capacitor coordinates under the identical/stiff-source limit; they do not mean three physical capacitors. Pre-clock configuration and explicit reset precharge the stage anchors; live patch recall and panic preserve Q charge. The damping law `d_ref = 0.2·10^(VQ/10) = 2·10^(−r)`, exponential in VQ between the printed endpoints, is applied to `r_effective=clamp(r_anchor(t)−deltaVq/10,0,1)` before the filter's source-loading correction. See [continuity implementation and limits](capacitor-continuity/README.md). The endpoints are printed (Q 5 at 0 V, Q 0.5 at 10 V); the exponential path between them was chosen by ear on 2026-10-20 over the earlier linear `d_ref=2−1.8*r`, and the clipping is not a measured chip saturation curve.

`filter_lfo` continues to specify LP octave depth. The HP path receives `47/150 = 0.3133333333` times that depth, from the separate SUB resistor paths at the levers' equal 1 oct/V. This is independent of editable HP/LP EG scales. **Existing patches with nonzero `filter_lfo` intentionally change sound.** PWM and oscillator/amp SUB routes are unchanged by this correction.

`amp_level` is a normalized common VCA LEVEL, bounded 0..1, default 1. It acts on both filtered and bypass-sine branches after their common coupling capacitor and before the amp EG, shared bus and ring. `filter_level` remains the filtered-branch-only control; `volume` remains the final master. The factory table's last column now drives `amp_level`, with master `.55`, instead of being folded into final volume. R7 sums LEVEL and SUB currents into the same LC node (service manual 1 p.14: L1 120k, L2 270k, L3 150k). Since 0.4.0 the common gain is `max(0, amp_level + 0.3375*tremolo*SUB + touch)`: the SUB VCA lever (PN3 SVR4, a linear 10k between SUO and ground, service manual 2 p.27) passes up to the 3 Vpp SUB through 120k, against LEVEL's 10 V through 270k, so (1.5/120k)/(10/270k) = 0.3375 of full LEVEL at full lever. The wiper feeds all four boards' 120k (R7 L1), 30k in all, so lever travel `x` gives the loaded fraction `x/(1+x(1−x)/3)`, at most 7.7 % low at mid-lever; `tremolo` is that loaded fraction, and the endpoints are exact. Positive SUB raises common gain and filter cutoff together, and the summed current closes the VCA at zero rather than multiplying two gains. Before 0.4.0 the law was an engineering `amp_level − tremolo*(.5−.5*SUB)`, which dipped below LEVEL and reached full depth. Existing pressure gain remains a separate compatibility factor; its optional modern velocity source is described below.

`expression` is the foot controller, 1 fully open (the hardware's default with no pedal plugged in, and an exact bypass) down to 0 fully closed. It is not a gain: the PRA photo-coupler's CdS cell sits between MI and MO, and closing it hands the signal to the 68k–2.2k/0.33 µF leg into the 0.0033 µF at MO and the A-10k VOLUME track. Midband level follows the guide's printed travel curve (0 to −40 dB over about 28 degrees, ±5 dB, digitized from the printed graph), and the cell's resistance is whatever reproduces it, so no CdS law is assumed. The network's own shape comes with it: fully closed, 65 Hz sits 4.8 dB and 30 Hz 9.7 dB above 1 kHz, and 10 kHz 6.4 dB below it.

`tremolo` and `ring_mix` are panel lever travel, and both B-10k tracks load what they drive: the SUB VCA lever delivers `x/(1+x(1−x)/3)` of SUO into R7's 30k, and the MODULATION lever crossfades dry against wet over `1+x(1−x)·10k/8.04k`, the expression network's input impedance at MI with the pedal open. Endpoints stay exact. `brilliance` and `resonance_offset` stay loaded bus voltages, so the engine applies no lever law to them. The lever law is a separate helper for front ends: `brillianceLeverVolts` and `resonanceLeverVolts` take lever travel to the loaded BR and RES bus voltages. Both levers are B-10K slide pots, BRILLIANCE a centre-click one: the CS-50 parts list and the CS-60 parts list carry the same part numbers, marked common to the CS-50 (the CS-50 PN2 sheet's C-100K is the outlier). BRILLIANCE is centre-tapped between −15 V (MIN) and +15 V (MAX) into 41.6k; RESONANCE runs from +10 V at MIN to ground at MAX into the eight pin-7 networks, 55k returning to the mean preset Q bus. See [the BRILLIANCE/RESONANCE research](research/brilliance-resonance-authenticity-2026-10-20.md). The remaining B-10k levers (attack, decay, depth, speed, touch, portamento) drive control-voltage destinations whose own laws are unresolved; their parameters stay in engineering units.

`output_trim_db` is a utility calibration gain, bounded −24..+24 dB, default 0, **after the complete circuit and FIR**. It changes neither internal nonlinear drive nor any state/latency. Zero bypasses the multiplication exactly. There is no limiter, AGC or per-block normalization. This is not an original CS-50 circuit control and a saved preset's calibration stimulus cannot guarantee a fixed peak for arbitrary performances.

Five sound-path native groups independently check cutoff nodal ratios and audio equivalence, eight capacitor KCL equations against production dynamics, control-state continuity, additive VCA placement/closure, factory LEVEL mapping, and post-FIR trim linearity. The current allocation witness exercises all 60 keys. Native/embedded parity includes active globals, live return-to-neutral, trim endpoints, four rates, eight scenes and 384,000 float32 samples. Historical hardware diagnostics remain conditional; they do not prove that adding these paths recovered the unknown physical settings of a recording.

## Optional modern velocity expression

`expression_source` / `Patch::expressionSource` is a numeric enum: 0 selects the existing smoothed channel pressure, 1 selects the current board's latched note-on velocity. The default is 0, including every native research preset. This is a host-performance adaptation, with no change to the modeled hardware's default path. The three existing `pressure_*` keys retain their names/ranges and use the selected scalar independently for each board: gain `1−depth*(1−e)`, HP/LP variable-gm shift `e*filterDepth` octaves, and SUB vibrato `e*vibratoDepth` cents. It does not add a velocity envelope or a new smoothing circuit.

Velocity lives with note ownership, not the sounding key voltage: release, MIDI damper and Sustain II retuning preserve it. Actual board assignment/retrigger stores the new note-on velocity. Zero-velocity note-on still means note-off. Pressure smoothing continues in velocity mode, making a live return to source 0 use the ordinary controller history. Source switches preserve gates, capacitor voltages and oscillator phase, but deliberately do not smooth an expression-gain step. Panic/reset retain their existing contracts; the next allocation supplies a fresh velocity.

`velocity_sensitivity` remains a separate legacy amplitude gain and can compound the selected expression level response if both depths are enabled. No Rack visibility or saved-patch default is implied by the core. A host migrating old patches must use missing source=0; new velocity patches should explicitly save source=1. Positive filter depth affects only variable gm: preserving a chosen reference-velocity tone requires `f_new=f_floor+(f_old−f_floor)*2^(−v_ref*depth)` for each cutoff above the floor, not scaling total Hz.

Five native groups verify the enum/input contract, mixed-velocity board isolation, release/retrigger/steal/pedal/Sustain II, live source continuity, actual audio equivalence for all three routes, zero-depth bit identity, and independent legacy velocity gain. The additional native/embedded stream exercises velocity and live switching at four rates. A separate frozen-b22 build comparison verifies the default route with nonzero pressure depths, moving pressure and polyphonic MIDI; these tests establish software behavior rather than analog accuracy.

## Source-timed oscillator conditioning experiment

The default VCO one-shot now follows the published nominal current/frequency calibration (59.728593us), and the reset setter extends to60us. OUT7 uses a conditioned plateau/step approximation, with the same ramp feeding saw and the ideal WSC sine fold. Analytic discontinuity corrections cover both outputs; the pulse clock/duty is unchanged. This intentionally changes saw/sine audio, especially upper notes. Exact clamp/slice behavior is unmeasured. The one-shot fraction r=f*tau now follows the charge-balance law up to r=.9 (the CS-50's own top, C6 on 4' with PITCH at full, is r=.38; the former r<=.35 clamp is retired), and the pulse comparator reads the same conditioned ramp, so its falling edge is at max(duty, r) ([VCO authenticity research](research/vco-authenticity-2026-10-20.md)). See [derivation, retained adverse benchmark and implementation limits](oscillator-conditioning/README.md). Earlier references to a provisional oscillator reset are historical; the new nominal inference still has unknown current/trim tolerances.


## Configurable polyphony and internal rate

`Synth::configure(voices, factor)` is separate from `Patch`: voices 1–16 and factors 1/2/4. Changed configurations require an unclocked, unassigned engine and reset all electrical/controller state. Identical configuration is a harmless no-op; live or invalid changes are rejected atomically. Reset retains the configuration. Adapters own live idle/tail-fade policy and saved settings.

All 16 voices and both FIR coefficient/history arrays are allocated during construction. Only the configured slots advance. The original first four reset draws and 4× coefficient/accumulation order are unchanged; extra slots use a separate deterministic initialization stream. Existing shared bus constants and per-voice gain remain fixed, so virtual polyphony does not represent a new physical resistor network or add hidden normalization. Native `voiceState()` retains its original first-four view; `allVoiceState()` exposes the entire allocation.

At 2×, the Kaiser FIR has 125 taps and cutoff .225 cycles/internal sample; at 4× it retains 249 taps and .1125. Both have nominal 31-host-sample linear-phase group delay. At 1× an exact 31-sample delay replaces the FIR. The final-of-factor output phase remains the legacy convention; the different qualities do not claim sample-identical event alignment. The internal rate controls all circuit coefficients and oscillator steps, including existing defensive high-frequency guards.

For audio NO, a discrete white source with variance `sigma²` has two-sided density `sigma²/internalFs`. Keeping an unscaled variance while reducing4× to1× raises that density by6.02dB. The source now multiplies audio noise by `sqrt(factor/4)`, preserving the4× density at each fixed host rate. Since 0.4.0 the shared source follows the guide's limiter amplifier (printed p.32: driven to its 30 Vpp saturation, "white noise of constant amplitude", trimmed to 3 Vpp, the waveforms' level). It is IC11-2 (gain 10M/10k) driven into its ±15 V rails by a one-pole Gaussian process. The bandwidth is an **estimate**: IC11-1's closed-loop pole, NJM4558 typical GBW 3 MHz/(1+1M/4.7k) = 14.03 kHz (`tc` = 11.34 µs). IC11-2 cannot follow the sign of that process: at the NJM4558's typical 1 V/µs slew rate, also an **estimate**, a rail-to-rail swing takes 30 µs, while the sign flips about every 18 µs, so most short excursions turn back before the rail. The guide's "driven to saturation" makes this the large-overdrive limit: the output slews at full rate toward the rail the input's sign selects. Against an ideal sign the body (up to 3 kHz) gains about 3.4 dB and the top loses 1.2 dB at 10 kHz, 4.4 dB at 15 kHz and 7 dB at 20 kHz (a 20 MHz simulation); at 1.7 V/µs the body gain is about 2.5 dB. The engine runs the Gaussian AR(1), pole `exp(-dt/tc)`, and the slewing limiter at `ceil(768 kHz/internalFs)` substeps per internal sample and averages them; that is within 0.3 dB of a 20 MHz reference at every rate. Ahead of IC11-1 the zener noise passes 0.047 µF into 100k to ground (service manual 2 p.8), a 33.86 Hz high-pass, applied to each Gaussian substep with the trapezoidal RC ahead of the limiter. With LP pole `a` and HP pole `b` the Gaussian correlation becomes `(a·e^(-a|t|) − b·e^(-b|t|))/(a−b)`; for an ideal sign the arcsine law keeps the high-pass as a shelf, about 11 dB less density at DC. With the slewing limiter it takes 1.2 dB off SUB-N RMS. IC11-1's own 10 µF into 10k‖100k (1.75 Hz) is negligible beside it. Audio NO density is the same at every quality and host rate, replacing the earlier `sqrt(factor/4)` scaling of a white sample; before the slew limit, an ideal sign scaled to its continuous density `2·tc·ln2` was 9.5 dB louder than 0.3.0's uniform white source at a 48 kHz host. The level moves with both estimates. The first substep of each sample takes its uniform draw from the shared stream, through Acklam's inverse normal CDF, and the others from a dedicated seeded stream, so the shared draw count/order and drift are unchanged. Full-engine nonlinear levels and high-band differences remain quality-dependent. [Noise-quality validation](validation/noise-quality/README.md) supersedes the earlier low-quality noise behavior; prior reports remain historical.

## Ring Depth automation continuity

Version 0.2.0 interpolates live Ring Depth targets over 20 ms, quantized to the internal clock. This is digital control dezippering, not an analog RC claim. The frequency law, envelope trajectory, carrier phase, passive coupling and 0.2–220 Hz range are unchanged. Initial configuration/reset set the exact saved target; repeated equal targets do not restart a ramp, reversals begin at the current value, and panic preserves the ongoing control interpolation. Native diagnostics expose the actual depth coordinate.

The independent tests check elapsed-time closed form and exact endpoints at all qualities, uninterrupted phase/envelopes, and removal of the instantaneous frequency step. Fixed-patch parent audio remains byte-identical. This addresses a demonstrated automation discontinuity; the user's exact host crackle was not captured and is not claimed to have been independently reproduced. ## Key assigner glide and touch routes (0.3.0)

Sources, verdicts and rejected items are in [hardware realism research](research/hardware-realism-2026-10-20.md). `glide_mode` 1/2 runs a per-board semitone counter toward the assigner key: the board's own note while held or damper-held, otherwise the last assigned key. Portamento integrates `2^((code−60)/12)` with `1−exp(−dt/tau)` per internal sample, where the KAS gate/integrator's three legs give tau: 108.9 ms (3.3 M) below 1.58 steps/s, 13.6 ms (470 k‖3.3 M) below 43.2, and the direct gate above that, which passes the counter's steps unsmoothed. Both thresholds assume a log-linear counter clock between the printed 11 s and 1.4 ms endpoints; the lever's PS-voltage law is not printed. The sample-hold copies `60+12·log2(voltage)` while the board is held or in Sustain II and holds it otherwise. Mode 0 keeps the previous integer key path bit for bit and only tracks the counter. Glide state survives panic and is cleared by `reset()`.

Same-key reuse runs before the idle search: a released, non-damper board whose note equals the pressed key is re-keyed. Touch BRILLIANCE and `pressure_wah` share the `hpSubRelativeScale` coupling. Touch vibrato adds `pressure_vibrato·expression/3` cents. `Ceres.hardware_realism_contracts` recomputes the counter, the Hz-domain integrator, both sustain modes, reuse and the touch laws independently. The expression, note-reuse and fast-note contracts now read touch from the LP cutoff, which carries the full depth.

Touch LEVEL adds `touchLevelScale·pressure_volume·expression` to the common VCA gain, with `touchLevelScale=(6/150k)/(10/270k)=1.08` from the R7 LC matrix and the 6.0 V touch calibration; zero depth is bit-identical. A note-on that finds every board held returns after the physical-key ledger records it, so it still counts for the ring trigger and its later note-off consumes only its own press. The expression and note-reuse contracts check touch LEVEL against an equivalent `amp_level` and legacy velocity gain; the configuration, note-reuse and fast-note contracts check the ignored press.

## Circuit details (0.4.0)

Channel pressure follows the touch pre-amplifier's RC: service manual 2 p.8 shows VR3's wiper reaching IC1-2 through 100k with 0.1 µF to the +15 V rail, τ = 10 ms. Velocity has no hardware path and keeps its 5 ms digital smoothing. `Ceres.voice_expression_contracts` checks the 10 ms step response on the LP cutoff.
