# Canonical DSP source

`Source/DSP/ceres.cpp` and `Source/DSP/ceres.hpp` are the only production DSP implementation. A host should pin this repository as a Git submodule and compile these files directly. Do not maintain a copied Rack-specific oscillator, filter or envelope implementation. The Rack project records the gitlink revision, embedded compile definition and compiled source inventory in its own release manifest.

The initial import is the tested canonical v0.10.0 model from `/tmp/ceres-cs50-1x8LGd`, recorded by original-file SHA256 in `EXPERIMENT_IMPORT.json`. The new product's version starts at 0.1.0. The experiment's isolated amplitude-bias, shared LP-bus and alternate decay candidates are deliberately absent. The temporary source is a provenance location, not a build dependency. Hardware recordings, downloaded schematics, fitting scripts and the large experiment archive were not imported.

## Embedded adaptation

`CERES_EMBEDDED_TARGET=1` removes `Patch::name`, native preset lookup and allocating measurement APIs. It adds no alternate sound model. The shared C-string and native string parameter setters accept the same numeric keys/ranges. The seven added panel controls extend the imported API; enum-like waveform/mode values clamp then round to the nearest declared integer. Invalid embedded construction rates fall back to 48 kHz; native construction retains its exception. Supported construction rates are finite 8000..384000 Hz. A host should validate its sample-rate property before construction.

The embedded library is compiled with `-fno-exceptions` in the native validation build. Its only owned heap allocation occurs during `Synth` construction; reset, panic, patch changes and processing reuse it. `Patch` is trivially copyable in this configuration. Native and embedded `Patch` layouts differ and must not be linked interchangeably. No filesystem, threading, SDK, plugin GUI, sample playback or host framework is used by the embedded translation unit. The current setter has 57 numeric keys, including four additions for sound-path control/output calibration and the optional expression-source selector.

The allocation witness interposes `new`/`new[]` around 512 blocks of 64 samples with parameter/controller changes and lifecycle events, plus 64 blocks explicitly activating mixed-velocity expression and live source changes. It is a bounded witness, not exhaustive host testing or a blanket interception of every platform allocator. Source inspection finds no direct realtime `malloc`/allocation calls. The separate Rack wrapper must establish its own property/event and buffer contracts.

## Model and parameter boundaries

The model has four free-running oscillator boards, finite oscillator reset, WSC waveform approximations, cascaded nonlinear two-integrator HP/LP filters, capacitor envelopes, per-voice/common output coupling, four-times oversampling and a 249-tap FIR decimator. Its normalized circuit voltages, nonlinear scales and several raw panel/preset-CV conversions remain provisional. The full research archive contains public-recording diagnostics, but those did not establish exact hardware calibration, complete original MIDI/gates or a universal fit.

Filter frequency parameters specify the total small-signal integrator frequency at MIDI 60; a fixed 4.7-Mohm feed contribution remains while keyboard/envelope controls scale only variable conductance. Master `tune_cents` affects the oscillator and both filter keyboard paths; `octave` affects oscillator footage only. `key_track` is an engineering control, not proof of an alternative hardware law. Filter initial/peak levels and HP/LP envelope scales retain their explicit engineering units.

Engineering attack times mean initial-to-peak duration; decay/release mean T60 relative to the target. The native hardware table uses a separately documented, related-model five-RC conversion. `global_release` is an ideal shared minimum release-time override, distinct from MIDI damper gating and from the CS-50 SUSTAIN I/II keyboard-CV modes. Optional attack headroom/current-limit controls are research parameters, not identified chip controls.

Output coupling uses the documented topology with a low-input-impedance VCA limit, fully conducting expression element and unloaded HIGH output assumptions. Downstream branch calibration and recording/interface loading remain uncertain. The direct sine bypass, absolute drive, Q/control calibration and oscillator reset duration must not be advertised as measured final values.

The model is deterministic within a given floating-point/compiler/math-library build. Cross-platform bit identity is not promised. No fast-math flag or silent oversampling reduction was introduced. Constructor-created FIR coefficients are built outside realtime processing. The bounded native tests do not establish a Reason target deadline: the four-voice nonlinear solver and decimator need separate 64-frame wrapper/SDK/host performance measurement.

## Added panel-control model

The ring/SUB-waveform/Sustain additions preserved the imported audio at ring mix 0, SUB sine and Sustain I in their historical regression. The later sound-path changes below intentionally correct nonzero SUB filter-depth settings and factory common-level placement. The ring bypass returns the previous bus value directly. New noise state consumes the existing shared white sample without another random draw, so oscillator initialization, noise and drift sequences remain unchanged. Native-only `voiceState()`, `modulationState()` and `soundPathState()` return read-only diagnostics; they are absent from the embedded ABI.

**Ring.** The Yamaha servicing guide and direct CS-50 PRA/Overall sheets put one ring processor after the voice sum, before expression/output. Its independent sine carrier multiplies the bus through an ideal balanced-product approximation to the µA796 topology. The wet branch includes the direct-sheet 10µF/10k output coupling (tau 0.1 s); the guide shows a conflicting capacitor value. The carrier now traverses the documented four-100µF passive PRA network before multiplication, using pin7−pin8 without gain normalization. Its six resistor paths are 33kΩ pin7-to-ground, 100Ω pin7-to-pin8, 820Ω pin8-to-audio-bias, 1.2kΩ pin8-to-local-supply, 1kΩ audio-bias-to-ground and 390Ω local-supply-to-ground. This is an ideal carrier-source/zero-incremental-IC-current limit. Audio-input loading, transistor distortion, carrier leakage and the wet gain trim are still unidentified. Unity multiplier scale and linear dry/wet mixing remain engineering choices. See [carrier implementation and checks](ring-carrier/README.md).

The carrier is free-running. An aggregate physical-key ledger, independent of voice stealing and MIDI damper, triggers the frequency envelope only at all-keys-up → any-key-down, consistent with the owner's manual printed page 15. Additional key presses are legato. Final physical key-up interrupts the attack/decay and selects a fixed release. Direct CS-50 PRA (service2 PDF16/printed22) feeds RT through 6.8k from +15V and 3.3k to ground: the unloaded 4.9009901 V, interpreted through the existing provisional five-RC law, gives **0.46781044 s T60**. The ring's different external timing path prevents treating that inference as calibration. The envelope uses a 1% attack-target headroom, retains charge on retrigger/live edits and is independent of `global_release`. Attack is time to peak; decay is T60. Depth is a positive octave excursion, not recovered slider volts. The guide's approximate 0.2–220 Hz carrier range bounds the total frequency including the envelope; this is a bounded interpretation, not a measured analog clipping law.

**SUB.** Sine, down saw, up saw and square share the free-running SUB clock. Analytic BLEP corrections soften discontinuities; waveform phase/polarity alignment is an engineering convention. All existing SUB destinations, including pressure vibrato, use this selected source. The independent PWM sine clock is unchanged. Direct PN3 selects SUB-N; the guide printed page 32 shows a **22k/0.1µF low-pass** (unloaded corner 72.343 Hz), distinct from audio NO level. Although the guide calls this source pink noise and the owner's text calls it white noise, the implementation follows that one-pole circuit rather than an ideal 1/f generator. The existing procedural white sample feeds the trapezoidal RC. A fixed sample-rate-derived normalization targets 0.25 RMS before a static tanh bound; the limiter's actual noise statistics/bandwidth and modulation level remain unknown. There is no block normalization, gain follower, key sync or rate-dependent sample-and-hold.

**Sustain I/II.** The guide printed pages 25–26 describes held key voltages in I and open sample/hold gates in II. The model stores note ownership separately from sounding key voltage. In II, nonheld/nonpedal boards mirror `lastAssignedKey` on assignments, key release, pedal-up, all-notes-off and a live I→II switch. II→I captures the current key voltage. Both VCO and HP/LP keyboard paths use it, while oscillator phase, filter capacitors and amp/filter envelope state and gates remain unchanged. Four-voice allocation still uses the existing idle/quietest-release/oldest-held software policy; exact Yamaha KAS scan timing is not emulated. Protecting MIDI-damper-held boards is an explicit modern adaptation because the original instrument's pedal path was expression. Ring's physical-key ledger ignores that damper protection. Panic clears voices and ring envelope/coupling while free oscillator phases continue; reset restores all seeded phases/controllers/states.

Validation covers independent RC attack/release equations, ring sidebands and dry/partial/wet signal connection, free-running carrier, more than four physically held keys, repeated presses, pedal rearm, sourced SUB-noise smoothing and route independence, and Sustain II's shared oscillator/filter pitch routing with continuous state. These are implementation checks, not hardware sound-match measurements.

## Shared cutoff/resonance controls and common VCA level

The primary components, page references, source hashes and an independent nodal calculation are in [the sound-path source audit](sound-path-gap-audit.md) and [its manifest](soundpath/source-manifest.json). This implementation uses an **anchored, stiff-source limit**: effective cutoff/resonance patch values remain the neutral reference. It does not reinterpret those existing values as raw preset voltages. Finite preset-bus impedances, passive pot taper/backfeed, chip control input current and individual calibration trims remain unidentified. These limits matter for absolute accuracy.

`brilliance` is a signed actual loaded BR-node voltage offset in volts, bounded −15..+15 with neutral 0. With preset/source nodes held stiff, the documented 39k manual path and BR paths 680k HP/220k LP give incremental octave gains `.7*39/680` and `.65*39/220` per volt. The `.7/.65` manual slopes remain provisional. Brilliance adds to the variable-gm exponent alongside keyboard and EG control; it never scales the fixed 4.7 MΩ feed conductance. It is not a recovered panel slider position or an automatic recreation of the earlier loaded-bus diagnostic patches.

`resonance_offset` is a signed change of the actual RES bus around the effective Q calibration, bounded −10..+10 V, neutral 0. Positive electrical voltage reduces Q. The real wiper range is 0..10 V, so the signed engineering range does not imply that all offsets are physically reachable from an unknown neutral. Each of the eight pin-7 nodes has 220k to its preset source, 220k to the shared RES source and 10 µF to ground. With stiff sources, zero chip input current and equal initial incremental charge, those eight networks reduce exactly to one shared delta state:

`d(deltaVq)/dt = (resonance_offset/2 − deltaVq) / 1.1 seconds`.

The sample update is the exact constant-input RC solution at the internal rate. It is continuous through note allocation, patch changes and audio panic; returning the offset to zero retains the capacitor tail. Only `reset()` clears the incremental charge. The original per-stage effective Q settings remain independent baseline anchors and still change immediately. The existing provisional law `d_ref=2−1.8*r` is retained by applying `r_effective=clamp(r_base−deltaVq/10,0,1)` before the filter's source-loading correction. The physical endpoints support the direction, but do not identify this intermediate law or make the clipping a measured chip saturation curve.

`filter_lfo` continues to specify LP octave depth. The HP path now receives `(.7/.65)*(47/150) = 0.3374358974` times that depth, from the separate SUB resistor paths and the same provisional manual slopes. This is independent of editable HP/LP EG scales. **Existing patches with nonzero `filter_lfo` intentionally change sound.** PWM and oscillator/amp SUB routes are unchanged by this correction.

`amp_level` is a normalized common VCA LEVEL, bounded 0..1, default 1. It acts on both filtered and bypass-sine branches after their common coupling capacitor and before the amp EG, shared bus and ring. `filter_level` remains the filtered-branch-only control; `volume` remains the final master. The factory table's last column now drives `amp_level`, with master `.55`, instead of being folded into final volume. R7 sums LEVEL and SUB currents into the same LC node, so the reduced common gain is `max(0, amp_level − tremolo*(.5+.5*SUB))`. At level 1 this preserves the previous tremolo gain exactly; at lower levels it models addition and gain closure rather than multiplying two gains. The inherited unipolar depth/DC convention and normalized closure threshold are engineering choices, not a calibrated 270k/120k pot-to-gain transfer. Existing pressure gain remains a separate compatibility factor; its optional modern velocity source is described below.

`output_trim_db` is a utility calibration gain, bounded −24..+24 dB, default 0, **after the complete circuit and FIR**. It changes neither internal nonlinear drive nor any state/latency. Zero bypasses the multiplication exactly. There is no limiter, AGC or per-block normalization. This is not an original CS-50 circuit control and a saved preset's calibration stimulus cannot guarantee a fixed peak for arbitrary performances.

Five sound-path native groups independently check cutoff nodal ratios and audio equivalence, eight capacitor KCL equations against production dynamics, control-state continuity, additive VCA placement/closure, factory LEVEL mapping, and post-FIR trim linearity. The current allocation witness exercises all 57 keys. Native/embedded parity includes active globals, live return-to-neutral, trim endpoints, four rates, eight scenes and 384,000 float32 samples. Historical hardware diagnostics remain conditional; they do not prove that adding these paths recovered the unknown physical settings of a recording.

## Optional modern velocity expression

`expression_source` / `Patch::expressionSource` is a numeric enum: 0 selects the existing smoothed channel pressure, 1 selects the current board's latched note-on velocity. The default is 0, including every native research preset. This is a host-performance adaptation, with no change to the modeled hardware's default path. The three existing `pressure_*` keys retain their names/ranges and use the selected scalar independently for each board: gain `1−depth*(1−e)`, HP/LP variable-gm shift `e*filterDepth` octaves, and SUB vibrato `e*vibratoDepth` cents. It does not add a velocity envelope or a new smoothing circuit.

Velocity lives with note ownership, not the sounding key voltage: release, MIDI damper and Sustain II retuning preserve it. Actual board assignment/retrigger/stealing stores the new note-on velocity. Zero-velocity note-on still means note-off. Pressure smoothing continues in velocity mode, making a live return to source 0 use the ordinary controller history. Source switches preserve gates, capacitor voltages and oscillator phase, but deliberately do not smooth an expression-gain step. Panic/reset retain their existing contracts; the next allocation supplies a fresh velocity.

`velocity_sensitivity` remains a separate legacy amplitude gain and can compound the selected expression level response if both depths are enabled. No Rack visibility or saved-patch default is implied by the core. A host migrating old patches must use missing source=0; new velocity patches should explicitly save source=1. Positive filter depth affects only variable gm: preserving a chosen reference-velocity tone requires `f_new=f_floor+(f_old−f_floor)*2^(−v_ref*depth)` for each cutoff above the floor, not scaling total Hz.

Five native groups verify the enum/input contract, mixed-velocity board isolation, release/retrigger/steal/pedal/Sustain II, live source continuity, actual audio equivalence for all three routes, zero-depth bit identity, and independent legacy velocity gain. The additional native/embedded stream exercises velocity and live switching at four rates. A separate frozen-b22 build comparison verifies the default route with nonzero pressure depths, moving pressure and polyphonic MIDI; these tests establish software behavior rather than analog accuracy.

## Reproduce current implementation checks

```sh
python3 Tools/check_embedded.py --build-dir build
python3 Tests/check_sound_path_parity.py build
```

These commands compare the current native and embedded builds and require no temporary experiment files. Each stream renders 384,000 samples across four rates and eight scenes, including repeated notes, stealing, live controls, sustain, panic and reset. The optional historical `--baseline-source` mode of `check_embedded.py` is not a current no-change assertion: that original driver contains nonzero `filter_lfo`, whose route has now intentionally changed. The exact original/native/embedded streams matched at the initial import; the saved reports preserve that earlier evidence. The `neutral` parity-driver argument disables only that intentionally changed route while retaining the prior panel controls for comparisons against commit `10e17fd`.

Run the same native/embedded driver with the new controls enabled:

```sh
./build/ceres_native_parity /tmp/ceres-panel-native.f32 controls
./build/ceres_embedded_parity /tmp/ceres-panel-embedded.f32 controls
cmp /tmp/ceres-panel-native.f32 /tmp/ceres-panel-embedded.f32
```

Each file contains 384,000 float32 samples. The `controls` argument enables ring blend/rate/depth/A/D, all five SUB shapes and both Sustain modes across the same four rates and allocation/pedal/reset sequences; `soundpath` additionally enables the new globals, VCA level and output trim. The prior recorded enabled-control comparison is [panel-enabled-parity.json](validation/panel-enabled-parity.json), and its prior unchanged-default comparison is [panel-default-parity.json](validation/panel-default-parity.json). Those and the initial-import reports remain historical evidence and are not overwritten.
